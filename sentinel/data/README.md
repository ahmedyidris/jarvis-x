# Data

- `sample_incidents.json` — 3 synthetic-but-realistic incidents used by
  `eval/eval_harness.py` to prove the pipeline runs end-to-end. Not a
  portfolio-strength eval set on its own.
- `runbooks/*.md` — the seed corpus for the vector store, one runbook per
  sample incident so retrieval has something correct to find.
- `vector_store.db` — generated by `scripts/seed_store.py`, gitignored.

## Scaling up to a real eval set
Pull a sample from [VOID](https://www.thevoid.community/), the public
incident/postmortem database (~10k+ real postmortems). Suggested first
step: sample 30-50, hand-label `expected_category` +
`expected_root_cause_keywords` the same way `sample_incidents.json` does,
and add their source postmortems to `runbooks/` (or split into a separate
`past_incidents/` corpus). No code changes needed — `eval_harness.py`
already reads whatever is in `sample_incidents.json`.
